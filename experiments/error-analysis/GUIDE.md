# 오답 원인 라벨링 가이드

---

## 1. 할 일

baseline과 시드 3개 run 모두 오답이면서 baseline이 정상 종료한 **147문항**을 4개로 나눠 각자 자기 몫을 라벨링하고, 서로의 몫을 돌아가며 한 명씩 검수한다.
문항마다 **baseline 응답 1개**를 읽고 오답 원인 라벨을 붙인다. (A, B, C, D 팀원예시)

| 구분 | 개수 | 처리 |
| --- | --- | --- |
| 직접 라벨링 | **147** | A 37, B 37, C 36, D 37 (과목이 번갈아 나오게 배정) |
| 정상 종료인데 답 추출 실패 | 3 | 별도 확인 (C) |
| 길이 초과(`length`) 종료 | 42 | 기존 반복 분석 결과로 규칙 라벨, 10개만 표본 확인 (C) |

각자에게 주는 자료: 문항, 보기, 이미지, 정답, baseline 응답 전문, 모델이 고른 답.

**검수 순서 (돌아가며 한 명씩)**

baseline오답 중 직접 분석하는 문항은 147문항으로 줄였는데,
그 기준은 제가 주말에 진행한 seed 실험(seed만 변경해보기, exp/baseline-seed-robustness에서 확인 가능)에서 정했습니다. baseline과 3개의 서로다른 seed에서 모두 틀리는 문항 147개가 분석 대상입니다.

```
 A의 몫 ──▶ B가 검수
 B의 몫 ──▶ C가 검수
 C의 몫 ──▶ D가 검수
 D의 몫 ──▶ A가 검수
```

## 2. 라벨 기준 (확정본, 라벨링 중 변경하지 않는다)

한 문항에 **라벨 하나**만 붙인다. 아래 순서로 질문하고 **처음 "예"가 나온 곳**에서 멈춘다.

```
 응답 전문 + 정답 + 이미지를 읽는다
      │
      ▼
 ① 모델이 최종으로 고른 답이 정답과 같은가?              ── 예 ──▶ evaluation_issue
      │ 아니오                                                  (채점이 잘못 읽음)
      ▼
 ② 문제 자체의 결함을 원문·이미지로 짚을 수 있는가?       ── 예 ──▶ question_defect
      │ 아니오
      ▼
 ③ 응답이 이미지 내용을 이미지와 다르게 서술했는가?       ── 예 ──▶ visual_reading
      │ 아니오
      ▼
 ④ 풀이에 필요한 개념·공식·사실을 틀리게 쓰거나 빠뜨렸나? ── 예 ──▶ knowledge
      │ 아니오
      ▼
 ⑤ 개념은 맞는데 계산·논리·보기 비교가 틀렸는가?         ── 예 ──▶ calculation_reasoning
      │ 아니오
      ▼
 ⑥ 자기수정을 반복하다 최종 답을 확정하지 못했는가?      ── 예 ──▶ repetition_incomplete
      │ 아니오
      ▼
 uncertain
```

| 순서 | 라벨 (`primary_type`) | 자세한 조건 | 필요한 증거 |
| --- | --- | --- | --- |
| ① | `evaluation_issue` | 응답의 **최종 선택**이 정답과 같은데 오답 처리됨. 또는 응답에 최종 선택이 없는데 채점 결과에는 답이 있음 | 최종 선택 문장 인용 |
| ② | `question_defect` | 다음 중 **하나를 직접 짚을 수 있을 때만**: 질문이 둘 이상으로 해석됨 / 보기가 불명확·중복 / 정답이 보기에 없음 / 정답이 둘 이상 / 정답 라벨이 문제 조건과 모순. **느낌만으로는 붙이지 않는다** | 어느 항목인지와 근거 한 줄 |
| ③ | `visual_reading` | 응답이 이미지의 수치·글자·도형 관계·대상을 **이미지와 다르게** 서술함. 이미지 없이 풀리는 문제에는 붙일 수 없음 | 응답 문장 인용 + 이미지의 실제 내용 한 줄 |
| ④ | `knowledge` | 이미지·문제 조건은 맞게 서술했는데 필요한 개념·공식·사실·용어를 틀리게 쓰거나 빠뜨림 | 틀린 문장 인용 + 필요한 개념 한 줄 |
| ⑤ | `calculation_reasoning` | 필요한 개념·조건을 맞게 썼는데 계산 실수, 논리 비약, 보기 비교 오류가 있음 | 틀어진 단계 인용 |
| ⑥ | `repetition_incomplete` | 자기수정을 반복하다 최종 답을 확정하지 못함, 결론이 계속 뒤집힘 | 뒤집히는 구간 인용 |
| ⑦ | `uncertain` | 위 증거를 대지 못함 | 이유 한 줄 |

**헷갈릴 때**

- **지식(④)과 추론(⑤)**: 정답 풀이에 필요한 개념·공식을 응답이 맞게 제시했는가? 맞게 제시하고 적용·계산이 틀리면 ⑤, 제시가 틀리거나 빠졌으면 ④.
- **이미지(③)와 지식(④)**: 응답이 이미지 내용을 맞게 서술했는가? 틀리게 서술했으면 ③, 맞게 서술하고 개념이 틀리면 ④.
- 두 가지가 섞여 보이면 **오류가 처음 생긴 지점**의 라벨을 붙이고 나머지는 `reason`에 적는다.
- 이미지가 필요한 문항에 ③이나 ④를 붙이려면 **이미지를 직접 열어 봐야 한다**.
- *증거를 못 대면 `uncertain`*이다. 기준이 모호해도 새 기준을 만들지 말고 `uncertain`으로 두고 `reason`에 이유를 적는다.

**확신도** (`confidence`): 3 = 응답 인용과 (필요하면) 이미지로 직접 확인함 / 2 = 한쪽 근거만 확인함 / 1 = 추정.

## 3. AI 사용 규칙

4명 모두 AI를 사용한다. 대신 아래 규칙과 4장의 검수로 품질을 지킨다.
**판단은 내가 하고, AI가 쓴 글을 그대로 붙이지 않는다.**

|  | 내용 |
| --- | --- |
| ○ 해도 됨 | 영어 응답의 **번역·요약(이해용)** / 모르는 개념 확인 / 이미지 설명 참고 / 라벨 후보를 물어보기 |
| ✕ 하면 안 됨 | AI가 쓴 **라벨, 근거, 이유를 그대로 복사해 붙이기** / 확인 없이 AI의 판단을 따르기 / AI가 만든 문장을 `evidence_quote`로 쓰기 |
| ◎ 반드시 | AI가 한 말은 **응답 원문, 이미지, 정답으로 내가 직접 확인**한 뒤에만 쓴다 |
| ◎ 번역할 때 | 모델 응답은 영어다. 번역본은 **이해용**이고, 판단의 근거가 되는 문장은 **영어 원문으로 다시 확인**한다. 번역에서 바뀌기 쉬운 곳(수치, 단위, 부정 표현 `not`/`never`, 선택지 문자 A~D, 최종 선택 문장)은 원문과 꼭 대조한다 |

**근거 인용은 영어 원문에서만**: `evidence_quote`는 **모델 응답 영어 원문에서 그대로** 복사한다. 번역문을 넣지 않고, 요약하거나 고쳐 쓰지 않는다 (자동 점검이 원문과 글자 단위로 대조한다). `reason`은 한국어로 써도 된다.

## 4. 검수

검수는 3단계다.

```
 ┌─────────────────────────────────────────────┐
 │ ① 자가 점검 (각자, 문항마다)                    │
 │    4개 모두 했으면 self_check = yes            │
 └──────────────────────┬──────────────────────┘
                        │ labels_<작성자>.csv 제출
                        ▼
 ┌─────────────────────────────────────────────┐
 │ ② 자동 점검 (A의 스크립트)                     │
 │    걸리면 작성한 사람이 수정 / 의심 항목은 ③으로  │
 └──────────────────────┬──────────────────────┘
                        ▼
 ┌─────────────────────────────────────────────┐
 │ ③ 교차 검수 — 돌아가며 한 명씩                  │
 │    B가 A의 몫, C가 B의 몫, D가 C의 몫, A가 D의 몫│
 │    · 무작위 8개: 라벨을 안 보고 다시 라벨 → 비교 │
 │    · 고위험 라벨 전부: 증거를 보고 동의 여부     │
 │    · 자동 점검 의심 항목: 확인                  │
 └──────────────────────┬──────────────────────┘
                        ▼
        같음 ──▶ 확정
        다름 ──▶ 두 사람이 원문·이미지를 같이 보고 협의 → 확정 + 변경 기록
        AI 복붙 의심 ──▶ 라벨을 쓴 사람이 그 문항을 직접 다시 라벨링
```

### ① 자가 점검 4개

1. 모델 응답을 처음부터 끝까지 읽었다. (번역본으로 읽었다면 근거 문장은 **영어 원문으로 다시 확인**했다.)
2. 이미지가 필요한 문항이면 이미지를 직접 열어 봤다.
3. 정답과 모델이 고른 답을 직접 대조했다.
4. `reason`을 내 말로 썼고 AI 문장을 그대로 붙이지 않았다.

### ② 자동 점검 항목

| 점검 | 걸리면 |
| --- | --- |
| `evidence_quote`가 해당 문항 응답 원문에 **그대로** 있는가 | 작성한 사람이 수정 |
| `primary_type`, `confidence`, `images_checked`가 허용된 값인가 | 작성한 사람이 수정 |
| 필수 열이 비어 있지 않은가 | 작성한 사람이 수정 |
| `self_check`가 `yes`인가 | 점검 후 수정 |
| `visual_reading` 또는 `knowledge`인데 이미지가 필요한 문항에서 `images_checked`가 `yes`가 아닌가 | 이미지 확인 후 수정 |
| `reason`이 다른 문항과 같거나 거의 같은가 | ③에서 우선 확인 |

### ③ 교차 검수 대상

| 대상 | `review_type` | 방식 |
| --- | --- | --- |
| 각자 몫에서 무작위 8개 (A 스크립트가 고정 seed로 지정) | `random` | 검수하는 사람이 라벨을 **보지 않고** 다시 라벨링한 뒤 비교 |
| 고위험 라벨 전부: `confidence=1`, `uncertain`, `question_defect`, `evaluation_issue` | `high_risk` | 라벨과 증거를 보고 동의 여부 확인 |
| ②에서 의심으로 걸린 항목 | `flagged` | 확인 |

검수하는 사람이 확인하는 5가지:

- (a) `evidence_quote`(영어 원문)가 라벨을 실제로 뒷받침하는가 (검수하는 사람도 번역이 아니라 **원문으로** 확인)
- (b) 2장의 순서대로 **처음 해당되는 라벨**인가
- (c) 이미지가 필요한 문항에서 ③·④ 판단이 이미지와 맞는가
- (d) (무작위 항목) 라벨을 보지 않고 다시 붙인 라벨이 같은가
- (e) `reason`이 그 문항에만 해당하는 내용인가 (복붙 의심 점검)

## 5. 결과 CSV 열 명세

결과는 CSV 두 개로 받는다. 자동 점검과 집계를 스크립트로 하기 위해서다.
공통: UTF-8, 첫 줄은 열 이름, 쉼표나 줄바꿈이 들어간 칸은 큰따옴표로 감싼다, **문항당 한 줄**.

### `labels_<작성자>.csv` (각자 자기 몫을 작성, 합쳐서 147줄)

| 열 | 값 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | 문항 id (예: `validation_Art_8`) | 필수 | 배포 자료의 id를 그대로 |
| `primary_type` | `evaluation_issue` / `question_defect` / `visual_reading` / `knowledge` / `calculation_reasoning` / `repetition_incomplete` / `uncertain` | 필수 | 2장의 라벨 하나 |
| `confidence` | `1` / `2` / `3` | 필수 | 2장의 확신도 |
| `evidence_quote` | 모델 응답 **영어 원문**의 문장 | 필수 | 원문에서 **그대로** 복사 (번역문 금지) |
| `reason` | 본인 말로 쓴 한 줄 (20~100자) | 필수 | 왜 이 라벨인지. 섞여 보이면 나머지 원인도 여기에 |
| `images_checked` | `yes` / `no` / `na` | 필수 | 이미지를 직접 열어 봤는가. 이미지가 필요 없는 문항은 `na` |
| `self_check` | `yes` | 필수 | 4장 ①의 4개를 모두 했을 때만 `yes` |
| `label_by` | `A` / `B` / `C` / `D` | 필수 | 이 라벨을 쓴 사람 |

### `review_<작성자>_by_<검수자>.csv` (검수할 때 작성)

| 열 | 값 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | 문항 id | 필수 |  |
| `review_type` | `random` / `high_risk` / `flagged` | 필수 | 4장 ③의 대상 구분 |
| `label_by` | `A` / `B` / `C` / `D` | 필수 | 원래 라벨을 쓴 사람 |
| `review_by` | `A` / `B` / `C` / `D` | 필수 | 검수한 사람 (1장의 순서) |
| `blind_label` | `primary_type`과 같은 값 | `random`일 때 필수 | 라벨을 보지 않고 다시 붙인 라벨 |
| `quote_supports` | `Y` / `N` | 필수 | (a) 증거가 라벨을 뒷받침하는가 |
| `order_ok` | `Y` / `N` | 필수 | (b) 처음 해당되는 라벨인가 |
| `image_ok` | `Y` / `N` / `na` | 필수 | (c) 이미지 판단이 맞는가 |
| `reason_specific` | `Y` / `N` | 필수 | (e) 그 문항에만 해당하는 이유인가 |
| `agree` | `Y` / `N` | 필수 | 최종적으로 원래 라벨에 동의하는가 (`random`은 `blind_label`과 같으면 `Y`) |
| `final_label` | `primary_type`과 같은 값 | 필수 | 협의 후 확정 라벨 (동의하면 원래 라벨) |
| `change_note` | 자유 서술 | `agree=N`일 때 필수 | 바꾼 이유 |
