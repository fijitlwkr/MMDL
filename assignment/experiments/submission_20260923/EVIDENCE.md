# 채점 방식 선택과 격차 분석의 실험 근거

이번 제출용 채점 묶음은 최신 raw 900문항에 **Qwen 규칙 + 객관식 Final Answer 100자 보완 + 미추출·충돌 Judge, length 강제 Judge 없음**을 적용한 **600/900(66.67%)** 결과다. 과제 기준 67.4%와의 차이는 −0.73%p다. 실험팀의 채점 근거 자료이며 팀 최종 baseline 실행의 지정과는 구분한다. 아래 실험은 답 추출 방식의 선택과 측정 점수의 변동을 설명하며, 기준 점수에 맞추기 위한 파서 선택 근거로 사용하지 않는다.

최신 입력 SHA-256: `ef23f0c49d9b1ae6c62b9625fbd52cce474a0c035c1a644cfa737e0967daa313`

## 1. Qwen 기본 파서와 Final Answer 보완을 선택한 이유

| 결정 | 관측 결과 | 근거와 해석 범위 |
|---|---|---|
| Qwen 규칙을 기본으로 사용 | H1의 파서 불일치 49건에서 검토 답과 Qwen 47건, MMMU 2건 일치 | [H1 보고서](../scoring_lab/legacy_pilot/h1/REPORT.md), [문항별 비교](../scoring_lab/legacy_pilot/h1/parser_comparison.jsonl). 해당 불일치군에서 모델이 낸 답을 읽는 능력의 비교이며, 전체 정답률 비교가 아님 |
| 객관식 Final Answer 100자 보완 | H2 고정 표본에서 검토 답과 100/100 일치. Qwen 미추출을 보완한 59건도 59/59 일치 | [H2 보고서](../scoring_lab/legacy_pilot/h2/REPORT.md), [문항별 비교](../scoring_lab/legacy_pilot/h2/parser_comparison.jsonl). 정상 종료 객관식의 보완 자동 채택군에 대한 검토 |
| 두 규칙이 충돌하면 Judge로 이동 | 보완 규칙이 답을 제시해도 Qwen과 다른 경우 자동으로 덮어쓰지 않음 | [실제 처리 코드](../raw_evaluation/evaluate.py). 미추출도 Judge로 이동 |

H1·H2는 seed 42, cap 9048의 **과거 899문항 pilot**에 관한 단일 검토자 자료다. H2 표본 선정 seed는 3407이며 추론 seed와 다르다. H1의 10건이 H2에 재사용되었으므로 독립된 149건으로 합산하지 않는다. 최신 raw의 사람 검증 완료 결과나 전체 추출 무오류의 증거로 일반화하지 않는다. 과거 보고서의 length 강제 Judge 문장은 당시 정책 기록이며 현재 제출 정책은 아니다.

최신 raw에서는 동일한 주관식·length 정책을 고정했을 때 Qwen 기본의 Judge 대상 543건이 보완 적용 후 363건으로 줄었다. 추가 자동 처리 184건, 충돌에 따른 Judge 이동 4건으로 **순감소 180건(33.15%)**이다. 이는 처리 경로의 감소이며 정답률 개선이나 실제 API 비용 감소율을 직접 증명하지 않는다. 대안 파서 전체에 대해 새 Judge 채점을 수행하지 않았으므로 그 최종 정확도 순위도 주장하지 않는다. 집계는 [비교 결과](results/comparisons.json)에서 확인할 수 있다.

## 2. length 강제 Judge를 제거한 이유

| 동일 raw 내 정책 비교 | 게이트 적용 | 게이트 제거 | 변화 |
|---|---:|---:|---:|
| 최신 수신 raw | 594/900 (66.00%) | 600/900 (66.67%) | +6문항 |
| 이전 9/21 raw | 609/900 (67.67%) | 608/900 (67.56%) | −1문항 |

종료 사유가 length라는 이유만으로 규칙 추출 결과를 Judge로 바꾸는 정책은 두 raw에서 일관된 이득을 보이지 않았다. 따라서 **추출 성공·충돌 여부로 처리 경로를 정하고, length는 분석용 정보로 유지**한다. 최신 raw에서는 18건이 Judge에서 자동 처리로 바뀌었으며, 정오 변화는 정답 증가 8건·감소 2건이었다. 최신 [변경 문항](results/changed_items.jsonl)과 [비교 집계](results/comparisons.json), 이전 raw의 [정책 변경 검증 기록](../raw_evaluation/VALIDATION.md)을 제공한다.

이는 점수가 가장 높은 정책을 고른다는 주장도, 게이트 제거가 항상 더 충실하게 답을 추출한다는 주장도 아니다. 명시적 Final Answer가 없더라도 기존 규칙이나 Judge가 응답 문맥에서 답을 추출할 수 있도록 한다. 규칙 미추출·충돌은 계속 Judge로 보내며, Judge의 유효하지 않은 출력과 추출 실패는 오답 처리한다.

## 3. Judge 모델 비교가 격차 분석에 필요한 이유

아래 비교는 **게이트가 적용된 동일 최신 raw**에서 자동 처리 537건, Judge 대상 363건, 프롬프트와 생성 설정을 고정하고 Judge 모델만 바꾼 결과다. 이번 묶음의 no-gate 점수와 구분한다.

| 집단 | GPT-4.1-mini | GPT-4o-mini |
|---|---:|---:|
| 전체 | 594/900 (66.00%) | 567/900 (63.00%) |
| 객관식 | 556/847 | 542/847 |
| 주관식 | 38/53 | 25/53 |
| 추론 length | 40/128 | 21/128 |
| 추론 stop | 554/772 | 546/772 |

모델 버전은 각각 `gpt-4.1-mini-2025-04-14`, `gpt-4o-mini-2024-07-18`이다. temperature 0, top_p 1, seed 3407, max_tokens 8을 동일하게 사용했다. 답은 83건에서 달랐고, 4o-mini 기준 정답 증가 5건·감소 32건으로 전체 점수가 3.00%p 낮아졌다. [비교 집계](results/comparisons.json)와 [900문항의 정책별 판정](results/policy_comparison.jsonl)에서 확인할 수 있다.

같은 추론 출력이어도 채점기에 따라 측정 점수가 변한다는 근거다. 높은 점수의 Judge가 더 정확하게 답을 추출한다거나, 공식 결과와의 격차가 Judge 때문에 발생했다는 인과 증거는 아니다. 따라서 보고서에는 생성 성능과 채점 방식의 영향을 구분해 기록한다.

## 4. MMMU 규칙 단독과 최종 하이브리드의 차이

최신 raw에서 MMMU 규칙 단독은 **452/900(50.22%)**, 최종 하이브리드는 **600/900(66.67%)**다. MMMU 비교에서는 파싱 실패 시 무작위 선택을 끄고 실패를 오답 처리했다. 이 차이에는 객관식 파서, Final Answer 보완, 주관식 처리, Judge 사용 여부가 함께 들어가므로 **16.44%p를 Judge 하나의 효과로 해석하지 않는다**. 집계는 [scores.json](results/scores.json), 문항별 차이는 [policy_comparison.jsonl](results/policy_comparison.jsonl)에 연결한다.

객관식 Judge에는 선택지와 모델 응답을 제공하되 정답 선택지 표시는 전달하지 않는다. 주관식은 Qwen 방식인 `A=참조답, B=Other Answers`를 사용하므로 **참조답이 보이는 판정**이다. 주관식까지 “gold를 보지 않는 추출”이라고 기술하지 않는다. 두 방식과 출처는 [평가 도구 설명](../raw_evaluation/README.md)에서 확인할 수 있다.

## 5. 제출 보고서에서 사용할 결론

파서 선택은 과거 H1·H2의 원문 답 추출 검토로 설명하고, 격차 분석은 동일 raw에서 채점 조건을 바꾼 비교로 설명한다. 최신 점수 66.67%와 과제 기준 67.4%의 차이는 관측값으로 제시하되, 그 원인을 이 실험만으로 확정하지 않는다. 기존 저장 응답을 재사용한 제출 자료의 정리·재집계에는 **추가 추론과 추가 API 호출이 없다**. 과거 Judge 비교를 수행할 때 발생한 API 호출까지 없었다는 뜻은 아니다.
