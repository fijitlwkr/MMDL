VLMEvalKit은 중간 비교 후 추가 실험 필요성이 없어 후보에서 제외했습니다. 기존 코드와 수치는 재현 근거로 남깁니다. H1/H2 고유 검토 문항은 139개이며 분모를 합치지 않습니다. 기존 H1의 ‘대부분’ 및 H2의 X=99%는 사전 확정 기준이 아니었으므로 사전 등록된 지지·기각으로 표현하지 않습니다.

## 당시 hybrid100의 MC 처리

1. `finish_reason=length`: 항상 공통 Judge, 규칙 답 자동 채택 금지.
2. 정상 종료에서 Qwen 답과 유효 Final Answer marker 답이 충돌: Judge.
3. 충돌 없이 Qwen이 유효 답 반환: Qwen 자동 채택.
4. Qwen 실패 + 유효 marker: marker 자동 채택.
5. 두 규칙 모두 실패: Judge.

marker는 기존 정규식에 매치되는 유효 선택지들이 모두 같고, 마지막 매치 끝부터 응답 끝까지 100자 이하여야 합니다. 100토큰 또는 응답 전체 100자 제한이 아닙니다. 이는 사용자 정의 규칙이며 의미적 모호함을 전부 판별하지 않습니다.

Judge는 당시 `gpt-4.1-mini-2025-04-14`를 공통 사용했습니다. 동일 요청의 캐시를 정책 간 재사용하며 완료된 추출 실패는 오답, API 오류·미완료는 pending으로 구분합니다. 랜덤 폴백은 사용하지 않습니다. open의 과거 A/B 변환은 MC 추출 실험과 별개입니다.

## 최신 팀 계획과 구분할 것

- 팀의 생성 설정: 공유 setup, vLLM 0.11.0, 생성 seed 3407, `max_new_tokens=8192`, HF 고정 revision. 실제 공통 설정은 추론팀의 설정 파일을 입력으로 받습니다.
- 팀의 주관식 기본안: MMMU `parse_open_response + eval_open`. 보존한 과거 도구의 A/B 변환 경로를 최종안이라고 쓰지 않습니다.
- 참고용 예시에 Judge 3종 비교가 포함되어 있습니다. 기존 실험은 공통 Judge 1종이며 Judge 자체의 육안 검증을 하지 않았습니다. 추가 비교를 확정하면 별도 모델별 캐시·표본·채택 기준을 먼저 정합니다.
- 9/20 명세 확정 시 정상 종료 파싱 실패에서 Judge fallback을 쓸지, 주관식 length의 처리, Final Answer 보완 후보 포함 여부를 정합니다.
- 사람 라벨의 `unique` / `ambiguous` / `no_answer` 기준, 표본 수·선정 방식과 ‘차이가 작다’의 기준을 새 실험 결과 전에 정합니다. 질문·선택지·raw는 제공하고 GT·파서·Judge 결과는 숨깁니다.
- label 일치율은 모델의 최종 답을 충실히 추출했는지이며 GT 정답률과 다릅니다. 불일치군만 검토한 H1을 전체 파서 정확도로 보고하지 않습니다.

## 과제 반영

실험은 `assignment/experiments/`, 보고서는 팀 분담에 따라 4·7·8절입니다. raw 수정·재추론은 하지 않습니다. 이번 업로드는 보고서 본문이나 공통 src를 변경하지 않습니다. 최종 HF raw에 대한 별도 검증 후 승인된 구현만 src로 전달합니다.

상세한 당시 설계는 [v0.8 원문](legacy_pilot/PROTOCOL_v08_original.md)에 보존했습니다. 그 문서의 8192 탐색·Judge 검증 범위 등은 당시 시점의 기록이며 최신 팀 결정과 구분합니다.
