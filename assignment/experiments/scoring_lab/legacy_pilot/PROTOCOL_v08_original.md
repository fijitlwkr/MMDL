# 실험팀 계획 v0.8 — 윤석 담당

작성: 2026-09-19. 상태: **legacy-pilot H1/H2 단일 검토자 결과 집계 완료 / 최종 HF 검증 및 팀 채택 기준 확정 전**.
현재 주 비교는 **Qwen 공식·MMMU 공식(no random) 및 hybrid100 후보이며, 모든 정책에 같은 Judge를 사용한다.** VLMEvalKit은 중간 실험에서 추가 비교 필요성이 없어 후보에서 제외(탈락)했으며, 기존 결과·코드는 근거로 보존한다.
공통 Judge 작업 기준은 **`gpt-4.1-mini-2025-04-14`로 확정**했다. 합성 1건의 계정 실호출은 성공했으며, 실제 MMMU 재채점은 미완료다. 기존 `gpt-3.5-turbo-0125` 결과는 과거 참고 기록으로 보존한다.
최신 범위 조정: **AI Judge 자체의 정확성·육안 검증은 제외한다.** 파서 자동 채택과 length 처리 검증은 유지한다.
H1~H4로 가설을 통합했다. **length는 본 채점에서 항상 공통 Judge로 보내며 자동 채택하지 않는다.**
최종 HF 원본 응답과 그에 대한 사람의 판정은 아직 없다. legacy-pilot의 H1 49건과 H2 100건 반환 라벨은 아래 진행 기록에 별도로 반영했다. 서로 다른 Judge 모델을 비교하는 실험이 아니다.
기존 TSV 결과는 탐색 근거로만 사용하며 새 HF 결과의 숫자로 옮기지 않는다.

v0.8 진행: legacy-pilot의 H1 49건과 H2 100건(중복10건, 고유139건)에 대한 단일 검토자 반환 라벨을 ID·해시·원문 근거와 대조했다. H1에서 Qwen 47/49, MMMU 2/49가 검토 답과 일치했고 기존 hybrid는 47건 일치·1건 오독·1건 Judge 전송이었다. [H1 결과](results/h1_returned_review_20260919/REPORT.md). H2는 **100/100 일치, Wilson 95% 구간 96.30~100%**, Qwen 실패를 추가 채택한 군도 **59/59 일치**다. [H2 결과](results/h2_returned_review_20260919/REPORT.md). H2 범위 밖의 H1 Chemistry_18 오독과 합성 모호 답 반례는 남아 있다. 독립 2인 검증·최종 HF 검증은 미완료다. 99%는 사전 확정된 기준이 아닌 제안 목표였으며, 결과에 맞춰 기준을 소급 확정하지 않는다.

## 1. 이번에 답할 질문

**모델이 실제로 낸 답을 더 정확하게 읽으면서 Judge 호출과 비용을 줄일 수 있는가?**

모델의 정답률과 추출 충실도를 구분한다. 예를 들어 정답 C인 문제에서 모델이 최종 B를 명시했다면, 파서 B는 **정확한 추출 / 모델 오답**이다. Judge가 C를 반환하면 점수는 올라도 추출은 잘못됐다.

### H1 분모 및 육안 범위

정상 종료 MC 응답을 ① 둘 다 성공·같은 답, ② 둘 다 성공·다른 답, ③ 한쪽만 성공, ④ 둘 다 실패로 구분한다. 주 일치율은 `① / (①+②)`이고, ③과 각 파서의 추출률도 함께 보고한다. ④를 “같은 답”으로 세지 않는다. 이번에는 ②의 49개를 우선 검토하고 ③의 ID 목록을 보존한다. 한쪽만 성공한 사례의 검증을 완료했다고 주장하지 않는다. 파서가 같은 오답을 추출할 수 있으므로 높은 일치율은 높은 추출 정확도와 같지 않다.

### H2의 X와 표본

X=99%는 목표 제안이며 공식 기준이 아니다. `모델의 실제 최종 답을 정확히 추출한 수 / 검토한 규칙 자동 채택 수`로 계산한다. GT 정답률을 이 분자에 넣지 않는다. 자동 채택군 전체를 보면 그 고정 raw에 대한 정확도이며, 표본만 보면 표본 크기·오류 수·신뢰구간을 병기한다. 관측치가 99%라고 미래 응답 전체에 99%를 보장하지 않는다. Qwen 실패를 새로 구제한 군과 기존 Qwen도 성공한 군을 따로 보여준다.

실행 초안은 **stop MC 중 유효 Final Answer marker가 있고 hybrid100이 자동 채택한 군에서 seed 3407로 100건을 무작위 추출**하는 것이다. 대상이 100건 이하면 전수 검토한다. Qwen만 성공하고 marker가 없는 행은 이 분모에서 제외한다. 표본 100건 중 오류 0건이면 관측 정확도는 100%지만, 양측 Wilson 95% 하한은 약 96.30%다. 동일한 이항모형에서 하한 99% 이상은 오류 0건으로 최소 381건이 필요하다. 이는 모집단으로 일반화할 때의 계산이며, 고정된 자동 채택군을 전수 검토하는 데 381건을 요구한다는 뜻은 아니다. 계산 방법: [NIST의 Wilson 구간 설명](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/propconf.htm).

표본에서 체계적 오독이 나오거나 추가 자동 채택군의 검증량이 부족하면 관측 비율만으로 채택하지 않는다. H2를 생략하면 Final Answer 추가 규칙을 검증 완료로 채택할 수 없다.

### H3는 처리 방침과 진단 가설을 구분

“length 자동 채택 금지”는 사전에 정한 처리 방침이다. 그 자체가 통계적 가설은 아니다. 별도 가설은 length에서 추출한 답의 정답률이 낮은지다. length 총 N건, 규칙 성공 M건, 그중 GT 정답 C건이면 `C/M`(추출 성공군 정답률)과 `C/N`(추출 실패를 오답으로 본 전체 length 규칙 점수)를 모두 기록한다. Judge로 얻은 최종 점수와 혼동하지 않는다.

**추가할 자동 진단:** 같은 캐시에서 length의 Judge 유효 답 / Z / 기타 추출 실패 / API 오류 / 미완료 수를 집계하고, 유효 답 중 GT 정답률과 전체 length 점수를 함께 기록한다. API 오류·미완료가 있으면 전체 점수는 확정값 대신 하한으로 표시한다. MC와 참조답을 사용하는 open 판정은 분리한다. Z와 기타 실패도 원문·실패 사유로 구분하며, 모든 실패를 Z라고 간주하지 않는다.

Judge가 최종 답 없는 응답에서 답을 추측할 가능성은 남아 있다. 그러나 유효 답/Z 비율이나 GT 정답률만으로 이를 입증하거나 배제할 수 없다. MC에서 균등 무작위 선택의 기대 정답률을 참고할 경우 **동일 분석 집합의 `mean(1 / 선택지 수)`**를 쓴다. 선택지 수가 다르면 일괄 25%가 아니다. 이는 진단용 참고선이며 LLM의 답 선택이 실제 균등 무작위라는 가정이나 추출 충실도 검증을 대신하지 않는다. Judge 육안 검증은 이번 범위에 추가하지 않는다.

### H4에 필요한 자료와 해석

가능하면 같은 context 한도에서 출력 cap만 달리한 HF 전량 결과를 추론팀에서 받는다. 최소 두 cap × 세 파서의 점수표를 만들고, 각 parser를 고정한 cap 변화량과 각 cap을 고정한 parser 변화량을 모두 제시한다. cap과 parser 조합에 따라 결론이 바뀌면 상호작용/판정 보류로 기록한다. stop/length 하위집단 간 단순 정답률 차이는 어려운 문항이 더 길게 생성되는 효과도 섞여 있어 cap 확대의 효과를 직접 측정한 것이 아니다. 기존 TSV 출력은 참고 자료로만 쓴다.

추론팀 전달 조건은 [INPUT_CONTRACT.md](INPUT_CONTRACT.md)의 H4 항목으로 명시한다. 8192 전후 탐색 중 일부 문항만 실행한 속도 시험은 전량 cap 효과 검증으로 대체하지 않는다. 한 번씩 실행한 비교에서는 실행 간 변동까지 분리했다고 주장하지 않는다.

### 기존 도구와의 연결

`lab.py prepare`는 기존 4개 parser/보조 후보 × 3 gate의 12개 조합을 보존한다. **본 결과는 `__always_judge` 정책을 사용**한다. `__none`은 H3의 규칙 결과 진단에만 사용하고 `__marker_exception`은 이번 채택 후보에서 제외한다. v0.8의 `focused_review.py`는 H1 공동 성공 불일치와 H2 marker 채택군 무작위 표본을 별도로 선정하고, 중복을 제거한 블라인드 라벨 파일을 만든다. `selection_private.json`은 기존 `audit-score` 표본 형식과 다르므로 해당 명령에 그대로 넣지 않는다. 사람 라벨을 받기 전 추출 정확도나 채택 기준 달성을 출력하지 않는다.

v0.7에서 공통 Judge 실행기를 구현했다. H3의 Judge 상태별 진단과 선택지 범위별 집계는 `execution_summary.json`에 출력된다. 소프트웨어 테스트 32개와 합성 1건의 공통 API 호출을 Pod에서 확인했다. 실제 HF 결과나 사람 라벨은 아직 없다. 기존 `audit-pack --random-n 100`만으로 H2의 marker 군 표본이 만들어지는 것은 아니다.

## 4. 자동 채택 규칙 — 실험 후보

### Qwen 규칙

고정 commit의 `can_infer`를 사용한다. 유효 선택지 외 `Z`/False는 추출 실패다. Qwen 공식 evaluator 전체가 아니라 그 규칙 부분을 비교한다.

### MMMU 규칙 + 랜덤 폴백 제거

고정 MMMU 함수의 선택지 문자/본문 추출 규칙을 사용한다. 원본의 random 선택 분기에 도달하면 실패로 돌린다. 빈 응답에 임의 답을 채우지 않는다.

### VLMEvalKit 규칙

고정 commit의 `can_infer`를 사용하고 `VERBOSE`는 unset으로 고정한다. 최신판이라고 주장하지 않고 commit을 함께 보고한다. Qwen과 같은 함수 이름이어도 문자 위치·긴 응답 본문 매칭 제한·answer-is 정규식이 다르므로 별도 후보로 취급한다.

### 기존 hybrid100

1. MC 응답에서 기존 정규식으로 Final Answer 뒤 A–I 중 유효 선택지를 찾는다.
2. 발견한 marker의 유효 선택지들이 전부 같아야 한다.
3. 마지막 일치가 끝난 지점부터 원문 끝까지 Python 문자열 길이가 100 이하여야 한다. **토큰 100개가 아니다.**
4. Qwen 결과와 marker가 다르면 Judge. 둘 중 하나만 성공하거나 둘이 같으면 자동 채택 후보.
5. 본 채점에서는 length이면 위 규칙의 성공 여부와 관계없이 항상 공통 Judge로 보낸다. 기존 코드의 `marker_exception`은 보존된 탐색 기능이며 이번 채택 후보가 아니다.

이 조건은 “최종 결론이 명백하다”를 완전히 보장하지 않는다. 부정문, `A or B`, marker 이후 재고/철회, A–I를 넘어선 선택지 등을 육안 확인한다. 기존 규칙을 몰래 강화해서 과거 결과와 같은 구현이라고 부르지 않는다.

## 5. 주관식은 별도 분석

Qwen/VLMEvalKit/hybrid는 실험의 공통 전처리로 채점 단계에서 A=참조답, B=Other Answers로 변환한다. 참조답은 생성 입력에 넣지 않는다. 이 Judge는 **참조답을 본 동치 판정**이다. toolkit 전체 전처리/채점의 완전 재현이라고 부르지 않는다.

MMMU open 규칙은 텍스트/숫자 후보 추출과 공식 정규화를 사용한다. Qwen의 A/B 판정과 의미가 다르므로 전체 점수 차이를 전부 “MC 파서 효과”로 해석하지 않는다. MC/open의 분모와 결과를 따로 보고한다.

블라인드 육안 1차에서는 open의 모델 최종 답 텍스트를 기록한다. 2차에서 참조답과의 동치 여부를 사람이 확인해야 한다. 현재 `audit-score`의 추출 충실도 집계는 **MC에 한정**하고 open은 별도 검토 대상으로 표시한다.

## 6. 공통 AI Judge 규격

- Judge는 고정된 채점 구성요소이며 이번 연구의 검증 대상이 아니다. 모델별 비교·Judge 출력의 별도 육안 라벨링은 하지 않는다. 아래 항목은 동일 조건 실행과 로그 보존을 위한 운영 명세다.
- **공통 Judge 확정: `gpt-4.1-mini-2025-04-14`**. snapshot을 고정하고 모든 파서·정책과 baseline/파인튜닝 후 평가에 같은 설정을 적용한다. 기존 `gpt-3.5-turbo-0125`의 2026-10-23 종료 예정에 대응하는 운영 기준 교체이며, 여러 Judge의 정확도를 비교하는 실험은 추가하지 않는다. [GPT-4.1 Mini 모델 명세](https://developers.openai.com/api/docs/models/gpt-4.1-mini), [종료 공지](https://developers.openai.com/api/docs/deprecations).
- 2026-09-19 공식 문서 기준 새 Judge의 일반 텍스트 가격은 입력 **$0.40/100만 토큰**, 출력 **$1.60/100만 토큰**이다. 현재 확인한 종료 공지에 이 snapshot은 없으며, 종료 예정인 GPT-4.1 nano 및 GPT-5 mini/nano와 구분한다. 미래 가용성을 보장하지 않는다. **계정의 모델/설정 수락은 합성 1건으로 확인했다(입력228/출력1, 약 $0.0000928). 새 Judge의 추출 충실도는 별도 검증하지 않았다.** 합성 연결 검사에서 인증·모델 ID·temperature0/top_p1/seed3407/max_tokens8 요청·B 응답·usage 로깅을 확인했다. 이 연결 점검을 Judge 정확성 검증으로 표현하지 않는다.
- 비교할 raw가 이미 있으면 Qwen 생성은 다시 하지 않고, 채택할 정책들의 Judge 대상 합집합만 새 공통 모델로 재채점한다. 기존 raw/규칙 출력은 보존하고 새 Judge 설정 파일·캐시·결과 폴더를 만든다. GPT-3.5 결과를 새 모델 결과로 재사용하거나 모델명만 바꾸지 않는다. 574/579 등 종전 점수는 새 Judge 점수가 아니다. 과제 입력을 만족하는 최종 HF raw가 없다면 그 추론은 별도로 필요하다.
- 보고서에는 “Qwen 규칙·프롬프트를 바탕으로 Judge 모델을 교체한 평가”라고 명시하고, Qwen 공식 evaluator와 완전히 동일한 설정이라고 부르지 않는다. 계정 접근이 막히거나 팀이 다른 모델을 정하면 일부 문항만 임의 대체하지 않고 전체 공통 Judge 기준을 갱신한다.
- 새 실행은 `temperature=0`, `top_p=1`, Judge `seed=3407`, 출력 8토큰, 1회 요청으로 고정했다. 실제 API에서 이 요청을 수락함을 확인했다. 생성 모델의 seed와 Judge seed는 별도 필드다. 기존 캐시에 이 값을 소급 적용했다고 쓰지 않는다. seed는 최선 노력 방식이며 결정성을 보장하지 않으므로 응답의 `system_fingerprint`가 있으면 보존하고 정책 간 동일 캐시를 재사용한다. [Chat Completions API 명세](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).
- 정책별 Judge 대상의 합집합을 고정한다. 한 문항에 한 번 얻은 공통 Judge 결과를 필요한 모든 파서/정책에 재사용한다. 정책별로 다시 호출해서 응답 변동을 섞지 않는다.
- MC에는 GT를 넣지 않는다. open의 A=참조답 변환은 예외이며 명시적으로 분리한다.
- 기존 Qwen 프롬프트를 보존한다. A–D 문구와 실제 선택지 범위가 다를 수 있는 점은 별도 프롬프트 한계로 기록하고, 바꾸면 새 실험으로 둔다.
- A–D 한계의 노출 규모는 MC 전체의 선택지 수 분포, 5개 이상인 수, 실제 라벨이 A–D 밖인 수, 해당 문항 중 정책별 Judge 대상 수와 합집합 수로 기록한다. 노출된 문항 수가 실제 오채점 수는 아니다. 결과를 보고 조용히 프롬프트를 수정하지 않는다.
- 응답 원문·파싱 결과·상태·모델 snapshot/ID·프롬프트 해시·토큰 usage·지연·시도 수를 남긴다.
- 의미적 추출 실패 Z를 정답이 나올 때까지 재시도하지 않는다. 첫 비교는 문항당 유효 응답 1개; 전송 오류 재시도는 정책/비용에 별도 기록한다.
- API 연결 오류/미완료는 **pending**. 완료된 추출 실패는 오답. 둘을 구분하고 pending이 있으면 확정 정확도를 출력하지 않는다.
- 모델·프롬프트·raw가 같은 캐시는 정책 간 재사용한다. `judge_settings_sha256`으로 sampling/출력 cap/재시도/응답 파싱 설정도 고정한다. 다른 설정 캐시를 합치지 않는다.
- 종전 $1/평가 가설은 현재 가격/실제 사용량을 대신하지 않는다. 합집합 실제 지출과 각 정책을 단독 실행할 경우의 비용을 구분한다.
- 공통 전송 코드 `judge_runner.py`를 구현했다. 기본 dry-run, 누적 예산 기본 $1.00, API 오류/중단 자동 재시도 금지, 모델·입력·설정·소스 해시 검증을 적용한다. 실행 방법은 [SHARED_JUDGE.md](SHARED_JUDGE.md)에 있다. 별도의 3모델 비교는 하지 않는다.

## 7. 파서 자동 채택의 육안 라벨링 방법

검증 대상은 **파서가 뽑은 답**이다. Judge 출력을 사람 라벨과 비교하는 실험은 제외한다. `audit-score`는 `--judge` 없이 실행한다.

1. H1은 정상 종료 MC의 parser 불일치군(서로 다른 유효 답 또는 한쪽만 성공)만 육안 확인한다. 일치군 전체의 정확도 주장은 하지 않는다.
2. H2는 정상 종료 MC의 Final Answer 규칙 자동 채택군을 별도로 검증한다. 가능하면 전수, 양이 많으면 사전에 정한 크기의 seed 3407 무작위 표본을 사용한다. H1과 겹치는 문항은 라벨을 재사용해도 되지만 집계 분모는 분리한다. H3의 정답률 기록은 GT와 코드로 계산하며 별도 전수 육안 검증을 요구하지 않는다.
3. 두 사람이 **질문·선택지 목록·응답 원문**을 보고 독립 판정한다. GT·파서/Judge 출력·표본 선정 사유는 숨긴다. 현재 `audit-pack`은 이 세 입력 필드를 이미 포함한다. `sampling.json`과 `items.jsonl`은 라벨러에게 먼저 주지 않는다.
4. `unique`: 모델이 최종적으로 채택한 답이 하나. `ambiguous`: 복수 후보/철회 등으로 하나를 확정 못함. `no_answer`: 결론 없음·거절·응답 공백 등.
5. 이전 A를 명확히 철회하고 B로 결론내렸으면 B. A와 B를 단순히 함께 언급했거나 `A or B`로 끝나면 ambiguous. 추론 중 등장한 문자나 마지막에 등장한 선택지만으로 결론을 만들어주지 않는다.
6. unique는 최종 답 근거를 원문에서 그대로 인용한다. 정답을 새로 풀거나 모델의 실수를 고치지 않는다.
7. 불일치 문항은 토론/제3자 검토 후 adjudicated gold를 별도로 만든다. 애매함이 해소되지 않으면 ambiguous를 유지한다.
8. 선택한 문항 전체를 완료한 뒤 집계한다. 라벨링이 쉬운 문항만 골라 완료본을 보고하지 않는다.

H1의 불일치 진단 표본과 H2의 자동 채택 검증 표본은 합쳐서 모집단 오추출률을 계산하지 않는다. H2를 무작위 표본으로 검증하면 해당 자동 채택 분모·오추출 수·Wilson 95% 구간을 보고한다. 소표본에서 오류 0건이어도 “왜곡 없음”이나 “오류율 1% 미만”을 보장하지 않는다.

라벨러 간 일치율/Cohen κ는 기준의 명확성을 확인하는 값이며 정답성 보증이 아니다. open 텍스트 표현 차이는 의미 검토가 필요하다.

## 8. 최종 채택 회의에서 결정할 것

- 기준 라우팅과 Judge 모델/프롬프트/실패 처리/재시도 정책을 버전으로 고정한다.
- 새 자동 채택군의 체계적 오독이 남아 있으면 규칙을 채택하지 않는다. 증거가 부족하면 “판정 보류”로 쓴다.
- H1의 “대부분” 기준, H2의 X와 표본 수, H4의 cap/비교 대상을 결과를 보기 전에 정한다. 표본 크기보다 정밀한 정확도 보장을 주장하지 않는다.
- 점수·추출 실패율·충실도·호출 수·비용을 함께 본다. validation 점수를 가장 높이는 규칙을 사후 선택하는 것은 피한다.
- 육안 사례로 규칙을 수정하면 같은 사례를 독립 검증이라고 재사용하지 않는다. 수정 근거와 재검증 집합을 구분한다.
- 확정 후 baseline/파인튜닝 모델에 동일 평가 버전을 적용한다.

## 9. 역할과 보고서 연결

일정상 우선순위는 **H1/H3 및 length Judge 자동 진단 필수, H2는 라벨링 여건에 따라 조건부, H4는 비교 가능한 HF cap 출력 수신 시 조건부**다. H1 불일치군 크기는 실제 집계 전에는 작다고 가정하지 않는다. 크기를 먼저 확인해 검토량을 정하고, 일부만 검토하면 그 범위를 명시한다.

| 업무 | 제안 담당 | 산출물 |
|---|---|---|
| H1/H2/H3, H4 채점 효과 집계, 라벨링 기준 | 윤석 | 비교표, 불일치 목록, 사례·검증 결과 |
| 공통 Judge 실행/캐시, usage·비용, 라벨링 집계 | 다른 실험팀원 | 공통 Judge 명세, 비용표, 육안 평가 집계 |
| raw 및 동일 조건의 생성 예산 비교 자료 전달(H4) | 추론팀 | INPUT_CONTRACT.md 묶음, cap별 결과·시간·비용 |
| 공동 | 전원 | 독립 라벨링, 최종 채점 규칙 합의 |

제출 §4: 최종 채택된 코드·규칙·출처·Judge 실패 정책.
§7: 생성 절단과 채점 오추출을 구분하고, 같은 raw의 비교 근거를 1000자 이내로 요약.
§8: 표본 크기, 공통 Judge의 정확성을 별도 검증하지 않았다는 범위, open 판정, 기존 TSV와 HF 차이, 미실시 실험. 동일 Judge를 사용했다는 사실을 “채점 왜곡 없음”의 증거로 쓰지 않는다.

과거 참고: TSV 9048에서 hybrid+length gate는 574/900, gate 제거는 579/900이었다. 이는 같은 raw·공통 Judge 캐시를 사용한 비교에서 관측한 순 5문항(약 0.56%p)의 채점 정책 차이다. 이 순 차이만으로 실행 노이즈 범위라고 단정하지 않는다. 일반화 여부는 문항별 쌍대 결과와 불확실성을 함께 보고 판단한다. 이 차이는 gate가 유익하다는 근거가 아니며, 원문 충실도 검증 없이 높은 점수의 정책을 선택하지 않는다.
